XTRESSÉ — SHARED LIVE CALENDAR  (now a small page + a cal-assets folder)
=======================================================================

WHY THIS IS DIFFERENT FROM LAST TIME
  The earlier version was one very large HTML file. GitHub's in-browser editor
  mangles big files, which is what caused the broken page (raw code on screen).
  This version is a small HTML page plus a "cal-assets" folder holding the
  fonts, logo, and script as normal files. Small files upload cleanly.

WHAT TO UPLOAD (three things, all to the SAME place in your repo where
consumer-calendar.html already lives — the repo root):
  consumer-calendar.html   -> replaces the old one
  cal-assets/  (folder)    -> NEW, holds the fonts, logo, and dc-runtime.js
  api/         (folder)    -> the calendar server file

IMPORTANT: use "Add file -> Upload files" and DRAG the items in.
Do NOT use the pencil/edit button to paste — that is what broke it before.

DO THESE 3 THINGS IN ORDER (all in the browser)

1) STORAGE  (shared memory for the calendar)
   Vercel -> xtresse-hub project -> Storage -> Create Database
   -> choose UPSTASH -> Redis -> Free plan -> create
   -> Connect it to the xtresse-hub project.

2) TEAM PASSWORD
   Vercel -> xtresse-hub project -> Settings -> Environment Variables -> Add:
        Name:  CALENDAR_EDIT_PASSWORD
        Value: (pick a password for the Branday team)
        tick Production (and the other two if shown) -> Save.

3) UPLOAD  (GitHub auto-deploys to Vercel)
   GitHub repo -> Add file -> Upload files
   -> drag in consumer-calendar.html, the cal-assets folder, and the api folder
   -> Commit. Vercel redeploys automatically.

CHECK IT
   Open  https://xtresse-hub-one.vercel.app/consumer-calendar.html
   - The calendar shows normally (no raw code, no \n, no red error).
   - Click an entry to open it (no password to view).
   - Type a change and press Save -> it asks for the team password.
   - In the Import popup: "Download template" and "Guidelines" links work.
   - Open in a second browser: changes appear there too (refresh ~30s).

IF SOMETHING LOOKS OFF
   In GitHub, open the commit you just made and choose "Revert" to restore the
   previous calendar, then tell me what you saw.
